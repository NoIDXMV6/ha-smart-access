# Smart Access — умный допуск на Home Assistant

Автоматическое открытие **шлагбаумов по «своим» машинам** и **калитки/двери по лицам** —
целиком на одной VM с HAOS, **без GPU и без внешних зависимостей**.
Внешним остаётся только **LLM/VLM-сервис** — и он **опционален**: система указывается
тремя параметрами (`url`, `token`, `имя модели`) и при её недоступности ничего не ломает.

> Работает с **любой** камерой, которая есть в Home Assistant: облачные шлагбаумы
> А.М.Видео и ЕГДС (без RTSP!), домофония Hikvision, любые RTSP-камеры.
> Исполнители тоже любые: `amvideo.open_barrier`, `egds.open_barrier`,
> `lock.unlock` (hikconnect), `cover.open_cover`, `button.press` — настраивается в UI.

---

## Как это устроено (всё на одной VM с HAOS)

```
┌──────────────────────── VM с HAOS ────────────────────────┐
│                                                            │
│  Home Assistant (core)                                     │
│   ├─ интеграция smart_access (HACS): сервисы, сенсоры, UI  │
│   └─ карточки с кнопками «Открыть» / «Обучить»             │
│                                                            │
│  Аддон Mosquitto (MQTT-брокер)                             │
│                                                            │
│  Аддон Frigate (детекция car/person)                       │
│   └─ детектор OpenVINO, device: CPU  ← GPU не нужен        │
│                                                            │
│  Аддон Smart Access Core (этот репозиторий)                │
│   ├─ МОСТ: камеры HA (в т.ч. облачные) → MJPEG :8100       │
│   ├─ МОЗГ: события Frigate → CLIP (машины) / SFace (лица)  │
│   │        → решение → вызов исполнителя через HA API      │
│   ├─ база «своих»: /media/smart_access (фото + эмбеддинги) │
│   └─ UI-панель: статус, обучение, генератор конфига        │
│                                                            │
└────────────────────────────────────────────────────────────┘
          │ только опционально: url + token + модель
          ▼
   VLM (Ollama на ПК с RTX 2060 / любой OpenAI-совместимый)
   — «второе мнение» в серой зоне; недоступен → решение локальное
```

Почему так:

* **Облачные камеры А.М.Видео (WSS MPEG1-TS) и ЕГДС (авторизованные снимки) не умеют
  в RTSP** — их не «скормить» Frigate напрямую. Мост аддона тянет кадры через
  `camera_proxy` самого HA (уже с авторизацией интеграций) и раздаёт их Frigate'у
  как обычный MJPEG `http://127.0.0.1:8100/mjpeg/<камера>`. Сработает и для
  Hikvision-домофонии, и для любой другой камерной сущности.
* **Решение принимает локальный CPU-пайплайн.** CLIP ViT-B/32 (int8, 89 МБ) для машин
  и YuNet+SFace (~39 МБ) для лиц работают на CPU быстрее секунды. Замеры:
  эмбеддинг 8 аугментаций — ~450 мс; детекция лица — ~70 мс; детекция объектов
  OpenVINO SSD 300×300 — 30–80 мс/кадр (5 fps — запас по ядрам).
* **LLM — не критический путь.** VLM используется только чтобы подтвердить
  совпадение «в серой зоне» (немного ниже порога) или, по желанию, каждое
  срабатывание. Сбой VLM = решение принимается локально. Circuit-breaker после
  сбоя держит паузу 60 с и не тормозит события.

## Установка (по шагам)

### Два компонента — нужны ОБА

Система состоит из двух частей, ставятся они из разных мест и отвечают за разное.
**Работает только пара: без аддона интеграции нечего слушать, без интеграции
аддон не может вызывать сервисы и показывать статус в HA.**

| | **Аддон Smart Access Core** | **Интеграция Smart Access** |
|---|---|---|
| Где ставится | Магазин аддонов (Настройки → Дополнения) | HACS (боковая панель) |
| Что это | Движок: мост камер, распознавание (CLIP/SFace), решения, своя веб-панель | Мост в Home Assistant: сенсоры `sensor.smart_access_*`, сервисы `smart_access.enroll/identify`, кнопка «Обучить» на карточках |
| Как выглядит | Пункт **Smart Access** в боковой панели | Настройки → Устройства и сервисы → **Smart Access** |
| Можно ли без второго | Нет — не сможет открывать шлагбаум и обучать из HA | Нет — в карточках будут жёлтые треугольники «объект не найден» |

**Вручную ставятся только сами пакеты** — Home Assistant не позволяет устанавливать
сторонние аддоны и интеграции без участия пользователя (платформенное ограничение,
одинаковое для любого решения). Каждая установка — буквально кнопка «Установить»:

| # | Компонент | Откуда | Занимает | Ручная настройка после установки |
|---|---|---|---|---|
| 1 | **Mosquitto broker** (MQTT) | Магазин аддонов, официальный — уже в списке | ~1 мин | Создать пользователя MQTT — 30 секунд |
| 2 | **Frigate** (детекция) | Магазин аддонов, добавить репозиторий `blakeblackshear/frigate-hass-addons` | ~5–10 мин | Вставить готовый конфиг (его сгенерирует панель Smart Access) и запустить |
| 3 | **Smart Access Core** (мост + мозг) | Магазин аддонов, добавить репозиторий `NoIDXMV6/ha-smart-access` | ~2–5 мин (готовый образ) | Заполнить поля в UI аддона: камеры, исполнители, VLM |
| 4 | **Интеграция Smart Access** | HACS, добавить репозиторий | ~1 мин + перезапуск HA | Короткий диалог: имена машин/людей, привязка камер |
| 5 | **Карточки «Открыть / Обучить»** | Скопировать YAML из `examples/cards/` в дашборд | ~2 мин | — |

Порядок строгий: 1 → 2 → 3 → 4 → 5 (Frigate и аддону нужен готовый Mosquitto,
интеграции — запущенный аддон). Смысл каждого шага расписан ниже.

Интеграции камер (amvideo-ha, egds-ha, hikconnect) в эту установку **не входят** —
они у вас уже работают, Smart Access лишь использует их сущности.

**Дальше всё работает автоматически**, руками не трогается:

* модели распознавания (CLIP, YuNet, SFace) **уже вшиты в образ аддона** — ничего
  не скачивается при работе, не нужен GPU и не нужен интернет; аугментации
  «ночь/дождь/снег» для пре-трейна генерируются на месте при обучении;
* мост облачных камер → MJPEG `:8100` для Frigate — запускается сам, адреса
  каждой камеры показывает панель;
* **конфиг Frigate** под ваши камеры — кнопка «Сгенерировать» в панели
  Smart Access, остаётся только вставить;
* MQTT-топики, сенсоры, кнопки, сервисы `smart_access.*` — создаёт интеграция;
* база «своих» машин и лиц — наполняется кнопкой «Обучить» на карточке или в панели;
* авто-открытие, cooldown, подтверждение кадрами, kill-switch, журнал — из коробки.

### Шаг 0. Требования

* HAOS в VM: **4+ vCPU, 8 ГБ RAM, 40+ ГБ диска** (GPU не нужен).
* Работающие интеграции камер: [amvideo-ha](https://github.com/NoIDXMV6/amvideo-ha),
  [egds-ha](https://github.com/NoIDXMV6/egds-ha), hikconnect — что у вас есть.

### Шаг 1. Mosquitto broker

Настройки → Дополнения → Магазин → **Mosquitto broker** → Установить → Запустить.
Создайте пользователя MQTT для Frigate — любым из двух способов:

* **Через пользователей HA** (проще всего): Настройки → Люди → Пользователи →
  «Добавить пользователя»: отображаемое имя любое, **имя пользователя** `mqtt`,
  пароль запишите. Mosquitto проверяет логины через систему пользователей HA,
  в самом аддоне настраивать ничего не нужно.
* **Через Logins в аддоне**: карточка аддона → Конфигурация → секция **Logins** →
  «Добавить» → username `mqtt`, пароль → Сохранить → перезапустить аддон.

Имя пользователя не может быть `homeassistant` или `addons` (зарезервированы).
Пароль затем указывается в конфиге Frigate (`mqtt: user / password`).

### Шаг 2. Frigate (аддоном, локально, на CPU)

1. Настройки → Дополнения → Магазин → три точки (справа сверху) → **Репозитории** →
   добавьте `https://github.com/blakeblackshear/frigate-hass-addons` → обновите.
   (Главный репозиторий `blakeblackshear/frigate` — только исходный код, магазин
   его отклонит с ошибкой «not a valid app repository».)
2. Установите **Frigate** — обычный, не «Frigate NVR Proxy» и не «Frigate (old CPU)»
   (вариант old CPU — только если процессор VM без поддержки AVX).
3. В карточке аддона включите, если выключено: «Показывать в боковой панели».
4. Конфиг Frigate находится **не** на странице «Конфигурация» аддона (там только
   порты и защита), а в самом Frigate. Откройте его веб-интерфейс (в боковой
   панели) → редактор конфигурации, либо файл
   `/addon_configs/ccab4aaf_frigate/config.yml` через File editor / Studio Code
   Server. Проще всего сгенерировать конфиг под ваши камеры: после Шага 4
   откройте панель **Smart Access → Конфиг Frigate → Сгенерировать** — и вставьте
   содержимое. Шаблон вручную:

```yaml
mqtt:
  host: core-mosquitto
  port: 1883
  user: mqtt
  password: ВАШ_ПАРОЛЬ_БРОКЕРА

detectors:
  cpu:
    type: openvino
    device: CPU
    model:
      path: /openvino-model/ssdlite_mobilenet_v2.xml
model:
  width: 300
  height: 300
  input_tensor: nhwc
  input_pixel_format: bgr
  labelmap_path: /openvino-model/coco_91cl_bkgr.txt

cameras:
  govorovo:                       # имя камеры как в Smart Access
    ffmpeg:
      inputs:
        - path: http://127.0.0.1:8100/mjpeg/govorovo   # MJPEG-мост аддона
          input_args: -f mjpeg
          roles:
            - detect
    detect:
      enabled: true
      fps: 5
      width: 1280
      height: 720
    objects:
      track:
        - car
    snapshots:
      enabled: true
      retain:
        default: 2
    record:
      enabled: false
```

5. Запустите Frigate. В логе не должно быть ошибок MQTT.

> **Локальные RTSP-камеры** (домофония/калитка и т.п.) идут во Frigate **напрямую**, без
> моста — это лучший путь: полный fps и разрешение. Укажите RTSP-URL в поле `rtsp_url`
> камеры в настройках аддона Smart Access (Шаг 3) — генератор сам подставит поток и
> `preset-rtsp-tcp` (TCP-транспорт, надёжнее для Hikvision). Мост нужен только облачным
> камерам без RTSP. Спецсимволы в пароле RTSP-URL кодируются: `@`→`%40`, `:`→`%3A`,
> `/`→`%2F`, `?`→`%3F`, `#`→`%23` (символ `!` менять не нужно).

### Шаг 3. Аддон Smart Access Core

1. Настройки → Дополнения → Магазин → три точки → **Репозитории** →
   добавьте `https://github.com/NoIDXMV6/ha-smart-access`. Репозиторий лёгкий
   (~1 МБ), добавляется за секунды.
2. Обновите магазин, в секции **Smart Access** найдите **Smart Access Core** →
   **Установить**.
   * Установка — это **скачивание готового Docker-образа** (~0,5 ГБ), а не сборка
     на месте: в карточке аддона виден прогресс, обычно 1–5 минут.
   * **Разово, после первой сборки образов в CI**: пакеты GHCR по умолчанию
     приватные — Supervisor не сможет их скачать и установка оборвётся ошибкой
     «failed to pull image». Откройте `github.com` → аватар справа сверху →
     **Your packages** → `smart-access-core-amd64` → ⚙ Package settings → внизу
     **Danger Zone → Change visibility → Public** (подтвердить вводом имени).
     Повторите для `smart-access-core-aarch64`. Это делается один раз; обновления
     после этого качаются без всяких логинов.
   * Если карточка в магазине не появилась — Supervisor отбраковал репозиторий:
     Настройки → Система → Журналы → выберите **Supervisor** и ищите строку
     `Can't read ... config.json`.
3. **Конфигурация аддона** (всё через UI, без файлов):

| Поле | Что указать |
|---|---|
| `cameras` (список) | Для каждого шлагбаума/калитки: `name` (латиницей, напр. `govorovo`), `ha_entity` — сущность камеры, `mode` — `car` (машины) / `face` (лица) / `car+face`, `executor_service` — какой сервис открывает (пример: `amvideo.open_barrier` или `switch.turn_on`), `executor_target` — сущность исполнителя (например `button.1_shlagbaum..._otkryt` или `switch.door_door_relay_0`), `rtsp_url` — для локальных камер с RTSP (например `rtsp://admin:пароль@192.168.168.77:554/h264/ch01/main/av_stream`): Frigate берёт поток напрямую, мост не используется; пусто = через мост, `cooldown` — сек между повторными открытиями (по умолчанию 45), `schedule` — окно работы `07:00-23:00` или пусто = всегда |
| `recognition` | Пороги: `car_threshold` (0.76), `face_threshold` (0.363), подтверждение кадрами `min_confirm_frames` (2), `bridge_fps` (1.5) |
| `vlm` | `enabled`: false/true; `base_url`: `http://<IP-ПК>:11434/v1` (Ollama), `api_key`: любой/ключ, `model`: `moondream`, `llava:7b`, `qwen2.5vl:3b`… `mode`: `gray_zone` (рекомендуется) / `verify_all` / `off` |
| `master_enable` | Глобальный kill-switch авто-допуска |

4. **Запустить**. В боковой панели появится **Smart Access** — панель управления:
   состояние моста/моделей/Frigate, база машин и лиц (обучение и удаление прямо
   там), журнал и генератор конфига Frigate.

### Шаг 4. Интеграция (HACS)

1. HACS → три точки → **Пользовательский репозиторий** → тип **Интеграция** →
   `https://github.com/NoIDXMV6/ha-smart-access` → Добавить.
2. Установите **Smart Access (умный допуск)** → перезапустите HA.
   (Это обязательный шаг, а не опция: именно интеграция создаёт `sensor.smart_access_*`
   и сервис «Обучить», на который ссылается карточка из Шага 5. Без неё в карточке —
   «объект не найден», а кнопка обучения ничего не отправляет.)
3. Настройки → Устройства и сервисы → найдена **Smart Access** → Настроить → Отправить.
4. В настройках интеграции (Конфигурация) укажите:
   * **Имена машин** и **имена людей** (для быстрого выбора subject);
   * **Привязку камер** для кнопки «Обучить» — по строке на камеру:
     `camera.1_shlagbaum_derevnia_govorovo_15072_kamera=car:Моя машина`

### Шаг 5. Карточки с кнопкой «Обучить»

Готовые карточки — в `examples/cards/` (обновлённые версии v1.1.0 из
[ha-barrier-cards](https://github.com/NoIDXMV6/ha-barrier-cards)). Отличие —
кнопка `mdi:camera-plus`: по нажатию кадр уходит в базу «своих» (имя — из
привязки камеры, по умолчанию «Моя машина»).

#### Пример: калитка Hikvision (домофония)

Полностью рабочий пример — `examples/cards/gate_hikvision.yaml`. Что нужно, чтобы он заработал:

1. **Добавьте камеру в HA** (если ещё не добавлена): Настройки → Устройства и
   сервисы → Добавить интеграцию → в поиске введите `generic` → выберите
   **Generic Camera** (в русском интерфейсе название не переводится, поэтому
   по слову «камера» её можно не найти):
   * Поток (Stream Source URL): `rtsp://admin:ПАРОЛЬ@192.168.168.77:554/h264/ch01/main/av_stream`;
   * RTSP transport: `tcp`;
   * Имя: `Калитка` → получится сущность `camera.kalitka`.
   Спецсимволы пароля в URL кодируются (`@`→`%40`, `:`→`%3A`…), символ `!` менять не нужно.
2. **В аддоне Smart Access Core** добавьте камеру:
   `name: kalitka`, `ha_entity: camera.kalitka`, `mode: face`,
   `executor_service: switch.turn_on`, `executor_target: switch.door_door_relay_0`,
   `rtsp_url: rtsp://admin:ПАРОЛЬ@192.168.168.77:554/h264/ch01/main/av_stream`
   (для экономии CPU можно указать низкий подпоток `.../h264/ch01/sub/av_stream`).
3. Перегенерируйте конфиг Frigate (панель → Конфиг Frigate → Сгенерировать) —
   калитка появится там с прямым RTSP-входом — и вставьте его в Frigate.
4. **Обучение лиц**: лучше через панель Smart Access → Лица (загрузка 2–3 фото
   каждого человека файлом, анфас, крупно). Кнопка `mdi:face-recognition` на
   карточке добавляет кадр для одного выбранного имени (`subject: Я` в карточке —
   поменяйте при необходимости).

### Шаг 6. Обучение и запуск

1. Откройте карточку шлагбаума, когда ваша машина стоит у шлагбаума, нажмите
   **«Обучить»** (или сделайте это в панели Smart Access). Снимок уходит в базу:
   система создаст 8 вариантов (ночь/дождь/снег/контражур) — это и есть
   «пре-трейн» под погоду и освещение. Повторите 2–3 раза при разном свете.
2. Для калитки: в панели Smart Access → Лица → добавьте по 2–3 фото каждого
   человека (анфас, крупно).
3. Проверьте: Инструменты разработчика → Действия → `smart_access.identify`
   (камера + тип) — результат придёт событием `smart_access_ack`.
4. Включите VLM (по желанию): на ПК с RTX 2060 у Ollama включите
   `OLLAMA_API_HOST=0.0.0.0`, в аддоне `base_url: http://<IP>:11434/v1`.

## Анализ «только CPU»: почему это работает без GPU

| Этап | Модель | Размер | CPU-время | Частота |
|---|---|---|---|---|
| Детекция объектов | SSD-Lite MobileNet v2 (OpenVINO, CPU) | ~5 МБ | 30–80 мс | непрерывно, 5 fps |
| Идентификация машины | CLIP ViT-B/32 int8 | 89 МБ | ~70 мс ×8 аугментаций | только при событии |
| Лица: детекция | YuNet | 0.2 МБ | ~35 мс | при событии person |
| Лица: сравнение | SFace | 39 МБ | ~40 мс | при событии person |
| VLM (опционально) | moondream/llava — на вашем ПК | — | — | серая зона/verify_all |

Пиковая нагрузка — 1–2 ядра на 5 fps детекции + короткие всплески при событиях.
На VM с 4 vCPU это ~20–35% CPU в сумме, всплески распознавания — доли секунды.
RTX 2060 остаётся занятой только VLM-моделью на вашем ПК (или вообще простаивает).

## Отказоустойчивость (система безопасности)

Сценарии проверены конструкцией:

* **VLM недоступен/медленный** — уверенные совпадения (выше порога) открываются
  как обычно; «серая зона» в этом случае безопасно остаётся закрытой; после сбоя
  circuit-breaker 60 с не тормозит обработку событий.
* **HA перезапускается** — аддон продолжает работать: события Frigate обрабатывает,
  статус пишет в MQTT (retained); попытки открытия повторяются (3 ретрая, backoff).
* **Frigate упал/перезапускается** — просто нет событий, остальное живо;
  связь восстановится автоматически (MQTT reconnect, HTTP без кэша).
* **Mosquitto перезапускается** — реконнект с экспоненциальной задержкой 2–30 с.
* **Камера недоступна** — мост отдаёт заглушку, счётчик сбоев виден в UI,
  попытки продолжаются.
* **Модели не загрузились** — статус `degraded`, авто-открытие **отключено**
  (fail-safe: система безопасности не действует вслепую), мост и UI работают.
* **Ложные срабатывания** — подтверждение N кадрами (по умолчанию 2), порог,
  серая зона + VLM, cooldown на пару камера+субъект, ограничение команд шлагбаума
  интеграциями (~20 с) учтено.
* **Kill-switch** — `master_enable` (в UI аддона и в настройках аддона):
  мгновенно запрещает все авто-открытия, остальное продолжает работать.
* **Чужие машины** — никаких уведомлений; кадры складываются в
  `/media/smart_access/unknown/` (чистка по `unknown_keep_days`), для обзора.

## Частые вопросы и проблемы

**«is not a valid app repository» при добавлении репозитория Frigate.**
Вы добавили главный репозиторий с исходным кодом `blakeblackshear/frigate` — в нём
нет аддонов. Удалите его из списка и добавьте репозиторий именно аддонов:
`https://github.com/blakeblackshear/frigate-hass-addons`, затем нажмите
«Обновить» в магазине.

**Frigate пишет ошибки MQTT (connection refused / auth failed).**
Проверьте: Mosquitto запущен; в конфиге Frigate `host: core-mosquitto`,
`port: 1883`; пользователь существует и пароль верный (создать — Настройки →
Люди → Пользователи, либо в аддоне Mosquitto секция Logins, после этого
аддон перезапустить); имя не `homeassistant`/`addons`.

**Камера в Frigate offline или чёрный кадр.**
Не работает MJPEG-мост: аддон Smart Access Core запущен? В его панели камера
«живая»? Имя в конфиге Frigate должно совпадать с `name` камеры в Smart Access
(латиницей, без пробелов), адрес — `http://127.0.0.1:8100/mjpeg/<имя>`.
Локальные RTSP-камеры подключайте напрямую, мост для них не нужен.

**Авто-открытие не срабатывает — чек-лист.**
1) `master_enable` включён (панель/конфиг аддона); 2) у камеры заполнены
`executor_service` и `executor_target`, и исполнитель срабатывает вручную
(Инструменты разработчика → Действия); 3) база обучена — 2–3 снимка этой
машины или лица именно с этой камеры; 4) Frigate распознаёт объект (события
`car`/`person` видны в журнале панели и в самом Frigate); 5) время внутри окна
`schedule`, cooldown истёк.

**VLM недоступен — это страшно?**
Нет. Уверенные совпадения (выше порога) открываются без него; «серая зона»
безопасно остаётся закрытой; после сбоя вызовы VLM приостанавливаются на 60 с
и не тормозят обработку. Проверьте лишь, что `base_url` заканчивается на `/v1`,
а у Ollama разрешён доступ по сети (`OLLAMA_API_HOST=0.0.0.0`).

**Нужен ли отдельный MQTT-пользователь для Smart Access?**
Нет — аддон берёт учётные данные брокера у Supervisor автоматически
(поля `mqtt` в настройках можно оставить пустыми). Пользователь `mqtt` нужен
только в конфиге Frigate.

**Нужно ставить и аддон Smart Access Core, и интеграцию из HACS — обе?**
Да, обязательно обе. **Аддон** = движок (мост камер, распознавание, решения,
своя панель в боковой панели). **Интеграция** = мост в Home Assistant
(сенсоры `sensor.smart_access_*`, сервисы `smart_access.enroll/identify`).
Без интеграции карточка покажет жёлтый треугольник «объект не найден», кнопка
«Обучить» не заработает, авто-открытие не сможет вызывать сервисы HA. Без аддона
интеграции нечего слушать. Таблица «кто за что отвечает» — в начале раздела
«Установка».

**Установка Smart Access Core «висит» — как понять, идёт ли она?**
Установка = скачивание готового Docker-образа ~0,5 ГБ. В карточке аддона виден
прогресс; на медленном канале это может занять 5–15 минут, полоса может подолгу
стоять на крупных слоях. Проверить, что скачивание реально идёт, можно по
сетевой активности VM или в Настройки → Система → Журналы → **Supervisor**
(строки вида `Downloading ...`). Если установка упала с ошибкой про образ
(`failed to pull image / manifest unknown / access denied`) — образы для вашей
версии ещё не собраны или пакеты GHCR не опубликованы (см. разовый шаг
публикации в Шаге 3).

**«Frigate работает с ONVIF, RTSP-поток добавить не получается».**
Наоборот: Frigate принимает именно **RTSP** — это его основной формат входа;
ONVIF используется только для автопоиска камер в мастере настройки (и у многих
Hikvision он выключен по умолчанию). Добавляйте камеру вручную: секция `cameras`
в конфиге Frigate (шаблон выше) или поле `rtsp_url` в аддоне Smart Access +
«Сгенерировать». Проверьте, что RTSP на камере включён (Hikvision:
Конфигурация → Видео/Аудио или Сеть → Дополнительно → Интегрированный протокол)
и транспорт TCP (`preset-rtsp-tcp` — уже в генераторе).

**В списке интеграций нет «Универсальной камеры» — как добавить RTSP-камеру в HA?**
Интеграция называется **Generic Camera** и в русском интерфейсе не переводится,
поэтому по слову «камера» она не находится. Наберите в поиске `generic` —
появится «Generic Camera». В ней заполните только «URL потока» (Stream Source
URL) вашим `rtsp://...`, транспорт — `TCP`; логин/пароль можно указать прямо в
URL. Появится сущность вида `camera.kalitka`.

**Где конфиг Frigate?**
Не на странице «Конфигурация» аддона (там только порты и защита), а в
веб-интерфейсе Frigate (редактор конфигурации) или в файле
`/addon_configs/ccab4aaf_frigate/config.yml` (File editor / Studio Code Server).
Быстрее всего: панель Smart Access → Конфиг Frigate → «Сгенерировать» → вставить.
