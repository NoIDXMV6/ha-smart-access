# Архитектура и решения

## Компоненты (одна VM с HAOS)

1. **Frigate (аддон)** — детекция объектов `car`/`person` на CPU (OpenVINO).
   Источники видео:
   * локальные RTSP-камеры — напрямую;
   * облачные камеры (А.М.Видео WSS MPEG1-TS, ЕГДС — снимки) — через **мост**
     аддона Smart Access Core (`camera_proxy` HA → MJPEG `:8100`).

2. **Smart Access Core (аддон)** — мозг:
   * подписка `frigate/events` (MQTT);
   * для события: кроп объекта через Frigate API (`/api/events/<id>/snapshot.jpg?crop=1`);
   * `car` → CLIP ViT-B/32 int8 → max cosine к прототипам базы «своих»;
   * `person` → YuNet → SFace → max cosine к базе лиц;
   * решение: порог + серая зона + VLM (опционально) + подтверждение N кадрами;
   * открытие: вызов HA-сервиса исполнителя через Supervisor-прокси
     (`amvideo.open_barrier` / `egds.open_barrier` / `lock.unlock` / `cover.open_cover`);
   * cooldown (камера+субъект), расписание, журнал, архив «unknown».

3. **Интеграция smart_access (HACS)** — HA-оболочка:
   * сервисы `smart_access.enroll` (кнопка «Обучить» на карточках) и
     `smart_access.identify` (тест);
   * сенсоры: `sensor.smart_access_status`, `sensor.smart_access_last_event`;
   * события `smart_access_event` / `smart_access_ack` для автоматизаций;
   * OptionsFlow: имена машин/людей, привязка камер.

4. **Mosquitto** — транспорт: Frigate ↔ аддон ↔ интеграция. Всё локально.

## «Пре-трейн» без GPU-обучения

Обучать сезонную модель на своих фото на CPU нерационально и ненадёжно. Вместо этого:

* backbone CLIP пре-трейнен на ~400 млн пар «изображение-текст» — сам по себе
  устойчив к сезонам, погоде, освещению, ракурсам;
* адаптация к вашим машинам — few-shot прототипы: каждое фото enrollment'а
  раскладывается на 8 аугментаций (яркость/контраст/гамма/насыщенность,
  расфокус, «дождевая дымка», отражение, микро-кропы) → эмбеддинги копятся в базе
  (окно 240 на subject);
* матчинг — max cosine по всем прототипам; серая зона отправляется на VLM.

## Почему не выбраны другие пути

* **Распознавание номеров (ANPR)** — камеры стоят неудачно, номера не читаются.
* **Frigate на отдельном хосте** — отклонено: всё должно быть на одной VM.
* **Уведомления на каждую машину** — шлагбаум общий, машин много: спам.
  Вместо этого — бесшовный допуск только «своих», чужие молча в архив.
* ** recognizer как отдельный docker-хост** — отклонено: всё в HAOS-аддоне.
* **ollama_vision / ollama-addon как обязательные части** — они завязаны на
  Ollama-специфичный API/каналы. Здесь VLM — «дополнительное мнение» через
  стандартный OpenAI-compatible endpoint (url+token+модель): Ollama, LM Studio,
  vLLM, OpenAI — что угодно; и любой сбой не влияет на работу.
* **frigate-hass-integration** — полезна (сущности камер/событий Frigate в HA),
  ставится по желанию через HACS; ядро Smart Access от неё не зависит
  (MQTT-топики стандартные), что упрощает восстановление.

## MQTT-топики

| Топик | Направление | Назначение |
|---|---|---|
| `frigate/events` | Frigate → аддон | события детекции |
| `smart_access/enroll/car` и `/face` | интеграция → аддон | обучение (base64 JPEG) |
| `smart_access/cmd/identify` | интеграция → аддон | тест распознавания |
| `smart_access/ack` | аддон → интеграция | ответ identify |
| `smart_access/event` | аддон → интеграция | допуски/отказы/обучение |
| `smart_access/status` (retained) | аддон → интеграция | статус каждые 30 с |

## Безопасность

* авто-открытие только при `master_enable` и загруженных моделях;
* fail-safe: при деградации распознавания открытие запрещено;
* `/data/options.json` не содержит секретов кроме пароля брокера (schema: password);
* UI аддона слушает :8099 на LAN — откройте только в доверенной сети;
* `SUPERVISOR_TOKEN` используется только внутри аддона.
