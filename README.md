# Smart Access — умный допуск на Home Assistant

Автоматическое открытие **шлагбаумов по «своим» машинам** и **калитки/двери по лицам** —
целиком на одной VM с HAOS, **без GPU и без внешних зависимостей**.
Внешним остаётся только **LLM/VLM-сервис** — и он **опционален**: система указывается
тремя параметрами (`url`, `token`, `имя модели`) и при её недоступности ничего не ломает.

> Работает с **любой** камерой, которая есть в Home Assistant: облачные шлагбаумы
> А.М.Видео и ЕГДС (без RTSP!), домофония Hikvision, любые RTSP-камеры.
> Исполнители тоже любые: `amvideo.open_barrier`, `egds.open_barrier`,
> `lock.unlock` (hikconnect), `cover.open_cover`, `button.press` — настраивается в UI.

## Как это устроено (всё на одной VM с HAOS)

```
┌──────────────────────── VM с HAOS ────────────────────────┐
│                                                            │
│  Home Assistant (core)                                     │
│   ├─ интеграция smart_access (HACS): сервисы, сенсоры, UI  │
│   └─ карточки с кнопками «Открыть» / «Обучить»             │
│                                                            │
│  Аддон Mosquitto (MQTT-брокер)                             │
│                                                            │
│  Аддон Frigate (детекция car/person)                       │
│   └─ детектор OpenVINO, device: CPU  ← GPU не нужен        │
│                                                            │
│  Аддон Smart Access Core (этот репозиторий)                │
│   ├─ МОСТ: камеры HA (в т.ч. облачные) → MJPEG :8100       │
│   ├─ МОЗГ: события Frigate → CLIP (машины) / SFace (лица)  │
│   │        → решение → вызов исполнителя через HA API      │
│   ├─ база «своих»: /media/smart_access (фото + эмбеддинги) │
│   └─ UI-панель: статус, обучение, генератор конфига        │
│                                                            │
└────────────────────────────────────────────────────────────┘
          │ только опционально: url + token + модель
          ▼
   VLM (Ollama на ПК с RTX 2060 / любой OpenAI-совместимый)
   — «второе мнение» в серой зоне; недоступен → решение локальное
```

Почему так:

* **Облачные камеры А.М.Видео (WSS MPEG1-TS) и ЕГДС (авторизованные снимки) не умеют
  в RTSP** — их не «скормить» Frigate напрямую. Мост аддона тянет кадры через
  `camera_proxy` самого HA (уже с авторизацией интеграций) и раздаёт их Frigate'у
  как обычный MJPEG `http://127.0.0.1:8100/mjpeg/<камера>`. Сработает и для
  Hikvision-домофонии, и для любой другой камерной сущности.
* **Решение принимает локальный CPU-пайплайн.** CLIP ViT-B/32 (int8, 89 МБ) для машин
  и YuNet+SFace (~39 МБ) для лиц работают на CPU быстрее секунды. Замеры:
  эмбеддинг 8 аугментаций — ~450 мс; детекция лица — ~70 мс; детекция объектов
  OpenVINO SSD 300×300 — 30–80 мс/кадр (5 fps — запас по ядрам).
* **LLM — не критический путь.** VLM используется только чтобы подтвердить
  совпадение «в серой зоне» (немного ниже порога) или, по желанию, каждое
  срабатывание. Сбой VLM = решение принимается локально. Circuit-breaker после
  сбоя держит паузу 60 с и не тормозит события.

## Установка (по шагам)

### Автоматически или вручную?

**Вручную ставятся только сами пакеты** — Home Assistant не позволяет устанавливать
сторонние аддоны и интеграции без участия пользователя (платформенное ограничение,
одинаковое для любого решения). Каждая установка — буквально кнопка «Установить»:

| # | Компонент | Откуда | Ручная настройка после установки |
|---|---|---|---|
| 1 | **Mosquitto broker** (MQTT) | Магазин аддонов, официальный — уже в списке | Создать пользователя MQTT — 30 секунд |
| 2 | **Frigate** (детекция) | Магазин аддонов, добавить репозиторий `blakeblackshear/frigate` | Вставить готовый конфиг (его сгенерирует панель Smart Access) и запустить |
| 3 | **Smart Access Core** (мост + мозг) | Магазин аддонов, добавить репозиторий `NoIDXMV6/ha-smart-access` | Заполнить поля в UI аддона: камеры, исполнители, VLM |
| 4 | **Интеграция Smart Access** | HACS, добавить репозиторий | Короткий диалог: имена машин/людей, привязка камер |
| 5 | **Карточки «Открыть / Обучить»** | Скопировать YAML из `examples/cards/` в дашборд | — |

Интеграции камер (amvideo-ha, egds-ha, hikconnect) в эту установку **не входят** —
они у вас уже работают, Smart Access лишь использует их сущности.

**Дальше всё работает автоматически**, руками не трогается:

* модели распознавания (CLIP, YuNet, SFace) **уже вшиты в аддон** — ничего не
  скачивается, не нужен GPU и не нужен интернет; аугментации «ночь/дождь/снег»
  для пре-трейна генерируются на месте при обучении;
* мост облачных камер → MJPEG `:8100` для Frigate — запускается сам, адреса
  каждой камеры показывает панель;
* **конфиг Frigate** под ваши камеры — кнопка «Сгенерировать» в панели
  Smart Access, остаётся только вставить;
* MQTT-топики, сенсоры, кнопки, сервисы `smart_access.*` — создаёт интеграция;
* база «своих» машин и лиц — наполняется кнопкой «Обучить» на карточке или в панели;
* авто-открытие, cooldown, подтверждение кадрами, kill-switch, журнал — из коробки.

### Шаг 0. Требования

* HAOS в VM: **4+ vCPU, 8 ГБ RAM, 40+ ГБ диска** (GPU не нужен).
* Работающие интеграции камер: [amvideo-ha](https://github.com/NoIDXMV6/amvideo-ha),
  [egds-ha](https://github.com/NoIDXMV6/egds-ha), hikconnect — что у вас есть.

### Шаг 1. Mosquitto broker

Настройки → Дополнения → Магазин → **Mosquitto broker** → Установить → Запустить.
В People → Users создайте пользователя (например `mqtt`) — он понадобится Frigate.

### Шаг 2. Frigate (аддоном, локально, на CPU)

1. Настройки → Дополнения → Магазин → три точки (справа сверху) → **Репозитории** →
   добавьте `https://github.com/blakeblackshear/frigate` → обновите.
2. Установите **Frigate** (полная версия, не NVR Proxy).
3. В карточке аддона включите, если выключено: «Показывать в боковой панели».
4. Конфиг Frigate находится **не** на странице «Конфигурация» аддона (там только
   порты и защита), а в самом Frigate. Откройте его веб-интерфейс (в боковой
   панели) → редактор конфигурации, либо файл
   `/addon_configs/ccab4aaf_frigate/config.yml` через File editor / Studio Code
   Server. Проще всего сгенерировать конфиг под ваши камеры: после Шага 4
   откройте панель **Smart Access → Конфиг Frigate → Сгенерировать** — и вставьте
   содержимое. Шаблон вручную:

```yaml
mqtt:
  host: core-mosquitto
  port: 1883
  user: mqtt
  password: ВАШ_ПАРОЛЬ_БРОКЕРА

detectors:
  cpu:
    type: openvino
    device: CPU
    model:
      path: /openvino-model/ssdlite_mobilenet_v2.xml
model:
  width: 300
  height: 300
  input_tensor: nhwc
  input_pixel_format: bgr
  labelmap_path: /openvino-model/coco_91cl_bkgr.txt

cameras:
  govorovo:                       # имя камеры как в Smart Access
    ffmpeg:
      inputs:
        - path: http://127.0.0.1:8100/mjpeg/govorovo   # MJPEG-мост аддона
          input_args: -f mjpeg
          roles:
            - detect
    detect:
      enabled: true
      fps: 5
      width: 1280
      height: 720
    objects:
      track:
        - car
    snapshots:
      enabled: true
      retain:
        default: 2
    record:
      enabled: false
```

5. Запустите Frigate. В логе не должно быть ошибок MQTT.

> Для **локальных RTSP-камер** (домофония и т.п.) подключайте их напрямую RTSP —
> минуя мост, это лучший путь. Мост нужен только облачным камерам.

### Шаг 3. Аддон Smart Access Core

1. Настройки → Дополнения → Магазин → три точки → **Репозитории** →
   добавьте `https://github.com/NoIDXMV6/ha-smart-access`.
2. Обновите магазин, найдите **Smart Access Core** → Установить
   (сборка образа займёт несколько минут — скачиваются python-пакеты).
3. **Конфигурация аддона** (всё через UI, без файлов):

| Поле | Что указать |
|---|---|
| `cameras` (список) | Для каждого шлагбаума/калитки: `name` (латиницей, напр. `govorovo`), `ha_entity` — сущность камеры, `mode` — `car` (машины) / `face` (лица) / `car+face`, `executor_service` — какой сервис открывает (пример: `amvideo.open_barrier`), `executor_target` — сущность исполнителя (например `button.1_shlagbaum..._otkryt` или `lock.gate`), `cooldown` — сек между повторными открытиями (по умолчанию 45), `schedule` — окно работы `07:00-23:00` или пусто = всегда |
| `recognition` | Пороги: `car_threshold` (0.76), `face_threshold` (0.363), подтверждение кадрами `min_confirm_frames` (2), `bridge_fps` (1.5) |
| `vlm` | `enabled`: false/true; `base_url`: `http://<IP-ПК>:11434/v1` (Ollama), `api_key`: любой/ключ, `model`: `moondream`, `llava:7b`, `qwen2.5vl:3b`… `mode`: `gray_zone` (рекомендуется) / `verify_all` / `off` |
| `master_enable` | Глобальный kill-switch авто-допуска |

4. **Запустить**. В боковой панели появится **Smart Access** — панель управления:
   состояние моста/моделей/Frigate, база машин и лиц (обучение и удаление прямо
   там), журнал и генератор конфига Frigate.

### Шаг 4. Интеграция (HACS)

1. HACS → три точки → **Пользовательский репозиторий** → тип **Интеграция** →
   `https://github.com/NoIDXMV6/ha-smart-access` → Добавить.
2. Установите **Smart Access (умный допуск)** → перезапустите HA.
3. Настройки → Устройства и сервисы → найдена **Smart Access** → Настроить → Отправить.
4. В настройках интеграции (Конфигурация) укажите:
   * **Имена машин** и **имена людей** (для быстрого выбора subject);
   * **Привязку камер** для кнопки «Обучить» — по строке на камеру:
     `camera.1_shlagbaum_derevnia_govorovo_15072_kamera=car:Моя машина`

### Шаг 5. Карточки с кнопкой «Обучить»

Готовые карточки — в `examples/cards/` (обновлённые версии v1.1.0 из
[ha-barrier-cards](https://github.com/NoIDXMV6/ha-barrier-cards)). Отличие —
кнопка `mdi:camera-plus`: по нажатию кадр уходит в базу «своих» (имя — из
привязки камеры, по умолчанию «Моя машина»).

### Шаг 6. Обучение и запуск

1. Откройте карточку шлагбаума, когда ваша машина стоит у шлагбаума, нажмите
   **«Обучить»** (или сделайте это в панели Smart Access). Снимок уходит в базу:
   система создаст 8 вариантов (ночь/дождь/снег/контражур) — это и есть
   «пре-трейн» под погоду и освещение. Повторите 2–3 раза при разном свете.
2. Для калитки: в панели Smart Access → Лица → добавьте по 2–3 фото каждого
   человека (анфас, крупно).
3. Проверьте: Инструменты разработчика → Действия → `smart_access.identify`
   (камера + тип) — результат придёт событием `smart_access_ack`.
4. Включите VLM (по желанию): на ПК с RTX 2060 у Ollama включите
   `OLLAMA_API_HOST=0.0.0.0`, в аддоне `base_url: http://<IP>:11434/v1`.

## Анализ «только CPU»: почему это работает без GPU

| Этап | Модель | Размер | CPU-время | Частота |
|---|---|---|---|---|
| Детекция объектов | SSD-Lite MobileNet v2 (OpenVINO, CPU) | ~5 МБ | 30–80 мс | непрерывно, 5 fps |
| Идентификация машины | CLIP ViT-B/32 int8 | 89 МБ | ~70 мс ×8 аугментаций | только при событии |
| Лица: детекция | YuNet | 0.2 МБ | ~35 мс | при событии person |
| Лица: сравнение | SFace | 39 МБ | ~40 мс | при событии person |
| VLM (опционально) | moondream/llava — на вашем ПК | — | — | серая зона/verify_all |

Пиковая нагрузка — 1–2 ядра на 5 fps детекции + короткие всплески при событиях.
На VM с 4 vCPU это ~20–35% CPU в сумме, всплески распознавания — доли секунды.
RTX 2060 остаётся занятой только VLM-моделью на вашем ПК (или вообще простаивает).

## Отказоустойчивость (система безопасности)

Сценарии проверены конструкцией:

* **VLM недоступен/медленный** — серая зона решается локально; после сбоя
  circuit-breaker 60 с; `verify_all` при сбое не блокирует решение.
* **HA перезапускается** — аддон продолжает работать: события Frigate обрабатывает,
  статус пишет в MQTT (retained); попытки открытия повторяются (3 ретрая, backoff).
* **Frigate упал/перезапускается** — просто нет событий, остальное живо;
  связь восстановится автоматически (MQTT reconnect, HTTP без кэша).
* **Mosquitto перезапускается** — реконнект с экспоненциальной задержкой 2–30 с.
* **Камера недоступна** — мост отдаёт заглушку, счётчик сбоев виден в UI,
  попытки продолжаются.
* **Модели не загрузились** — статус `degraded`, авто-открытие **отключено**
  (fail-safe: система безопасности не действует вслепую), мост и UI работают.
* **Ложные срабатывания** — подтверждение N кадрами (по умолчанию 2), порог,
  серая зона + VLM, cooldown на пару камера+субъект, ограничение команд шлагбаума
  интеграциями (~20 с) учтено.
* **Kill-switch** — `master_enable` (в UI аддона и в настройках аддона):
  мгновенно запрещает все авто-открытия, остальное продолжает работать.
* **Чужие машины** — никаких уведомлений; кадры складываются в
  `/media/smart_access/unknown/` (чистка по `unknown_keep_days`), для обзора.

## Файлы

* `addon/smart-access-core/` — аддон: мост, мозг, UI (Python, CPU, офлайн-модели).
* `custom_components/smart_access/` — интеграция (HACS): сервисы, сенсоры, настройки.
* `examples/cards/` — карточки v1.1.0 с кнопкой «Обучить».
* `examples/automations/` — уведомление о допуске (не спамит).
