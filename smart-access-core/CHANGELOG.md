# 1.1.6

- Диагностика Frigate в панели вместо молчаливого «нет связи»: `/api/status`
  теперь возвращает `frigate_error` — понятную причину (неверный порт,
  соединение отклонено, HTML вместо API) и что делать. Подсказка различает
  главные ошибки: порт 8556 у аддона Frigate — это WebRTC (go2rtc), HTTP API
  живёт на порту 5000; для доступа из соседнего аддона порт 5000 надо
  опубликовать (Frigate → Конфигурация → Сеть → «Unauthenticated Web
  interface» → 5000).
- Проверка Frigate больше не блокирует event loop синхронным requests
  (запрос в executor + кэш 10 с) — панель перестаёт «подвисать», если адрес
  Frigate недоступен/медленный.
- Генератор конфига Frigate исправлен под сетевую модель аддонов:
  * `mqtt.host` из опций (localhost/127.0.0.1/пусто) заменяется на
    `core-mosquitto` — аддон Frigate работает в мостовой сети hassio и не видит
    localhost, брокер для него — соседний аддон по имени;
  * мост камер подставляется как `http://172.30.32.1:8100/mjpeg/<name>`
    (шлюз hassio-сети = хост, где слушает Smart Access с host_network), а не
    `127.0.0.1:8100`, который у Frigate указывал на его собственный контейнер.
- UI: текст причины ошибки Frigate показывается в карточке «Состояние»
  (с экранированием), сообщение об ошибке загрузки статуса теперь содержит
  саму ошибку fetch — проще диагностировать ingress-сбои.

# 1.1.5

- Исправление: приложение пропадало из Магазина аддонов после 1.1.4. В свежих
  версиях Supervisor `watchdog` в config.json — это не булево значение, а
  строка-URL (как `webui`); `"watchdog": true` не проходит валидацию, и
  Supervisor молча отбраковывает приложение при сканировании репозитория.
  Установлено `"watchdog": "http://[HOST]:[PORT:8099]"` — Supervisor пингует
  web-интерфейс и перезапускает контейнер, если тот не отвечает.
- Схема config.json сверена с исходниками Supervisor (apps/validate.py):
  все остальные ключи валидны, `init: false` — корректное булево поле.

# 1.1.4

- Исправление crash loop `s6-overlay-suexec: fatal: can only run as pid 1`:
  Supervisor по умолчанию запускает контейнер аддона с docker `--init` (tini
  становится PID 1), а s6-overlay из базового образа HA обязан быть PID 1 —
  контейнер умирал мгновенно, до Python дело не доходило. Добавлены
  `"init": false` (s6 становится PID 1) и `"watchdog": true` (авто-рестарт
  при падении).
- run.sh подключён как главная служба: `COPY run.sh /run.sh` +
  `CMD ["/run.sh"]` — s6-overlay v3 запускает CMD автоматически.

# 1.1.3

- Исправление падения при старте (crash loop): код копировался в образ плоско
  (`COPY app /app`), а `main.py` импортирует `from app import ...` — пакет `app`
  в контейнере не находился, процесс завершался с `ModuleNotFoundError` сразу
  после запуска. Теперь код кладётся пакетом `/app/app`, задан `PYTHONPATH=/app`,
  путь в `sys.path` вычисляется от расположения файла (устойчиво к обеим
  компоновкам).
- В образ добавлены системные библиотеки `libstdc++6` и `zlib1g`, которые нужны
  opencv/onnxruntime и отсутствуют в минимальном базовом образе HA.

# 1.1.2

- Установка стала быстрой и с прогрессом: Supervisor больше не собирает образ
  на устройстве, а скачивает готовый из GHCR (`ghcr.io/noidxmv6/smart-access-core-{arch}`,
  собирает GitHub Actions). Из образа убран ffmpeg (кодом не использовался) —
  объём скачивания заметно меньше.
- Модели (CLIP/SFace/YuNet, ~128 МБ) больше не хранятся в git-репозитории —
  раздаются через GitHub Release `models-v1`, в образ вшивает CI; при их
  отсутствии run.sh скачает их при первом запуске. Добавление репозитория
  в Магазин аддонов теперь занимает секунды вместо минут.
